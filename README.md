# AI Agents See Security Website

Professional, responsive multi-page website for **AI Agents See Security**, designed for SMB audiences and focused on the primary conversion:

- Request a Security Assessment

Secondary conversion:

- Book a Consultation

## Project structure

- `assets/css/styles.css` – shared design system and responsive styles
- `assets/js/main.js` – mobile nav, footer year, reveal animations
- `*.html` – all requested pages
- `server.js` – local static server
- `tests/smoke.mjs` – basic smoke test for all pages and key CTA text

## Run locally

```bash
npm start
```

Then open:

- `http://localhost:8080`

## Run smoke tests

```bash
npm test
```

## Notes

### Shared visual system

All pages use the globe hero's near-black surfaces, pale-blue actions, editorial
headings, and restrained borders. Shared theme tokens and component states live in
`assets/css/styles.css`. Green, amber, and coral remain reserved for feedback and
priority indicators. Run `npm run test:theme` with Google Chrome installed to check
all 17 pages at three widths, text contrast, form errors, quiz states, and navigation.
Preview screenshots are written to the system temporary directory.

### Homepage globe

The borderless globe uses COBE (MIT) with its bundled world map. It is decorative,
not a representation of client locations or live monitoring. Runtime assets are
local; no CDN or external map request is needed. The globe pauses offscreen and
has a keyboard-accessible pause control. Reduced-motion and non-WebGL browsers
receive a static globe poster.

The threat overlay is an explicitly labelled simulation, not real attack data or
attribution to any city. Twelve example routes show bot traffic and intrusion
attempts with moving packets and arrival rings. The globe and overlay share one
animation clock, pause control, and reduced-motion preference. Static trails remain
available without WebGL. No network traffic is generated by this visualization.
Edit routes and geographic projection in `assets/js/globe-attacks.js`.

- Edit `assets/js/globe-source.js`, then run `npm run build:globe`.
- `npm run build` also rebuilds the globe and retains third-party notices.
- `npm run test:globe` runs rendering and responsive tests using locally installed Google Chrome.
- To regenerate the poster from this site's renderer, run `node tests/globe-browser.mjs --update-poster`.
- Browser tests write preview screenshots to the system temporary directory.

Install dependencies with `npm ci` before building or running browser tests.

### Dedicated Threat Map

`threat-map.html` is separate from the homepage globe. It shows geographic points,
an accessible observation list, source attribution, UTC timestamps, and filters for
time, category, source priority, source, and title/location search. The Resources
page and shared footer link to it. Its basemap and scripts are served locally;
opening the page makes no third-party map or threat-provider requests.

**No real threat provider is connected by default.** The page starts not connected
and offers an explicit, fictional demo that is never installed as a production
feed. It does not claim live attack visibility. Point locations describe approximate
infrastructure, not attacker identity, origin, or attack routes.

- Client source: `assets/js/threat-map-source.js`; build with `npm run build:threat-map`.
- Full `npm run build` rebuilds the basemap, browser bundle and footer.
- Run `npm run test:threat-map` for schema, reader, endpoint and browser tests (Google Chrome required).
- Basemap: Natural Earth public-domain data via World Atlas (ISC); notice retained in `assets/images/threat-world-LICENSE.txt`. Geographic libraries are build-time only.

#### Connecting an approved export

Set `THREAT_FEED_FILE` to an absolute path to an operator-managed JSON snapshot
**outside publicly served directories**, then restart the Node server. Without this
environment variable, `GET /api/threat-map` returns `unconfigured`. The endpoint is
GET-only, uncached by browsers, and never accepts a path or URL from a visitor.

This is a normalized-export reader, **not a third-party connector**. Before enabling
a source, review its redistribution license, attribution requirements, timestamp
semantics, geolocation accuracy, privacy obligations and update cadence. An importer
must keep provider credentials server-side, exclude personal/private records, apply
the provider's categories honestly, and atomically replace the export (write a
temporary file then rename). Do not advance `generatedAt` on an unchanged old export
merely to make its status current. The approval flag is operator attestation, not an
automated licensing check. Choose and implement a provider adapter separately.

The exact validation contract is `lib/threat-feed-schema.js`:

- Root: `version: 1`, `publicDisplayApproved: true`, `generatedAt` (UTC ISO timestamp), `sources` (1–20), and `records` (0–200).
- Each source: unique `id`, `name`, HTTPS `url` without credentials, `attribution`, and `license` text describing permission to display this export.
- Each record: unique `id`, a matching `sourceId`, `title`, `summary`, `observedAt` (source-reported UTC ISO timestamp), `category`, `priority`, and `location`.
- Categories: `malware`, `phishing`, `bot`, `malicious-infrastructure`.
- Priorities: `unknown`, `low`, `medium`, `high`; use `unknown` if not supplied.
- Location: explicitly `null` if unknown, otherwise numeric `latitude` (±90), `longitude` (±180), and a human-readable `label`. Do not guess missing locations.
- Strings are bounded; source URLs are HTTPS only. Times cannot be over a minute in the future; observation times cannot be over a minute newer than the export.
- Files above 512 KiB, invalid snapshots, and nonregular files are rejected. Unknown fields are stripped before public output; approved text fields must still be reviewed for privacy. HTML-like strings render as text, not markup.

The server checks the file at most once per 30 seconds. The visible page requests an
update once per minute. `current` means the snapshot is at most 15 minutes old—not
that an attack is happening now. `stale` retains older observations. `offline`
means the file, response or network could not be read/validated, and retains the
last valid snapshot when available. Server retention is in memory until restart;
browser retention is in memory until navigation/reload, including across demo use.

Feed updated = export generation time. Last server check = last attempted file read.
Last valid import = last successful read/validation, even of an unchanged export.
Record timestamps always remain separate. Empty snapshots/results do not imply an
absence of threats, and last-good data is never relabelled current after a failure.
